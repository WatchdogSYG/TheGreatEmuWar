# Release Notes - The Great Emu War
## Developer Summary
This update fixed a bug where certain spots would be out of the Emu navigation area, and a quick improvement to the gun materials so that players can tell the difference between guns with the same model, as I only have 2 models on hand right now.

Technical improvements make it easier to change and develop weapons, and prepare the game for multiplayer features in the future.
## Balancing
- None.
## Features & Content
- Non-starter pistol guns are now different colours, allowing for easier differentiation in lieu of models.
## Bug Fixes
- Standing right next to an `InvisibleWall` actor caused the Emus to stop chasing the player. Fix: disable navmesh collision on `InvisibleWall` so that there is no `NavMeshAgent` width buffer around the Actor.
## Technical
- Character spawning is now handled via `OnPostLogin()` and supports multiplayer spawning and instantiation. The remainder of multiplayer features remains incomplete, to be worked on as required. The game remains single player until it is feasible to change to multiplayer, but multiplayer architecture will be considered at all points in development.
- Subclassed all weapons as an `EchoWeapon` which handles the weapon cooldowns and states.
	- The character needs only to check for character animation states to determine if the weapon can be fired.
	- Weapons are now referred to by an `EchoWeapon` reference rather than a `FWeapon` struct of weapon stats and soft references.
	- Weapon switching and getting now involves switching on the int `CurrentWeaponIndex` to find an `EchoWeapon` reference, rather than storing weapon states in arrays and accessing via a `TArray.Get(CurrentWeaponIndex)` method call. 
	- Moved relevant content assets into the `EchoWeapon` directory to be modularised.
	- Wallbuys now store an `EchoWeapon` actor class reference rather than a `DataTableRow` to instantiate a weapon on the character weapon slot.
