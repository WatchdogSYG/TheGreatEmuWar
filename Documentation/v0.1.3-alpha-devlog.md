# Technical

## EchoGameSystems
A new module was created. The intent is to store all general classes there, with EmuGame extending classes in EchoGameSystems as a depenedency, so that EmuGame is eventually a subset of EchoGame.
### EchoGameSystems: Blueprint CombatAction
CombatActions are anything that can be triggered to perform an action in the context of combat. EchoWeapon and EchoAbility are children of EchoCombatAction.
The EchoCombatAction defines timings and resource checks that define the flow of a combat action. For example, it checks ammo or mana, and then starts the channelling state, where an animation may be played. Then after a time, it fires and enters recovery. The final flow is not finalised yet, so I have not included a diagram.
Weapons and Abilities differ only slightly, where weapons explicitly require a SkeletalMesh, and abilities don't. They also differ in data definition. The data struct passed in to define timings and other members are different.
The next step is to ensure replication is correct, and to set flags and flag checks so that animations may be played and cancelled appropriately.
### EchoGameSystems: Online Subsystems
Unreal provides the OnlineSubsystem interface to connect to Steam, among other platforms. The game is now set as a 400 appid (Spacewar) which is the testing appid reserved by Steam. The game can read and display friends from Steam, when Steam is active. I need to extend more functionality, such as joining lobbies and rich presence on steam, as well as provide sufficient feedback to the player when Steam is not available. i.e. a LAN connection mode or greyed out icons to show that the game is not connected (rather than a software error).
# Art Pass

This update's art pass involves development of Niagara assets. Namely a smoke effect that can also be repurposed into an explosion, and a muzzle flash asset.

## Niagara Smoke and Explosion Effect
A new museum map was created (not accessible to the player) to display the results of the Niagara smoke and explosion effects.

The smoke consists of the mesh on the left, which is a combination of icospheres. 
![](Assets/Pasted%20image%2020260531145303.png)

The mesh material is a masked voronoi, where the masking amount is affected by two dynamic material parameters, controlled by the Niagara Emitter.

![](Assets/Pasted%20image%2020260531145508.png)

![](Assets/Pasted%20image%2020260531145721.png)

The colour is linked to the ParticleAge. It uses an RGBA Gradient `ColorCurve` to define the colours it cycles through. This must be set directly in the editor in the Niagara component. It resets upon movement of the system, and there is no documentation on how to programatically set the asset upon instantiation. Future work is required to fix this, otherwise I will have to create a separate asset every time a colour pallete changes. This isn't the worst but it would be nice to programatically set the colour.

![](Assets/Pasted%20image%2020260531145850.png)

The explosion effect uses the same smoke particles but with different velocities and drag. Two emitters are set up, one has no z velocity to create a torus of particles, and one is a quicker effect but is radial.
